## 1. 목적 (Goal)

당일 확정된 TODO 목록과 사용자 보유 캐릭터를 입력받아, 각 TODO에 1명의 캐릭터를 매핑하고 **TODO 내용과 무관한** 캐릭터 페르소나/외형 기반 퀘스트 텍스트를 LLM으로 생성한다.

생성 결과만 반환한다. 저장·이벤트 발행·카운터 관리는 호출자 책임.

---

## 2. 책임 범위

### 2.1 본 에이전트가 수행하는 일

- 입력 검증 (한도 환산, 빈 입력 처리)
- 캐릭터 풀 라운드 로직 (중복 방지 + 라운드 리셋)
- LLM 컨텍스트 조립 (TODO 내용 미포함 보장)
- LLM 호출 및 재시도
- 성공/실패 항목 분리된 결과 반환

### 2.2 본 에이전트가 수행하지 않는 일 (호출자 위임)

- 일일 카운터 저장·증감 (Redis 등)
- 카운터 리셋 시점 결정 (자정/타임존)
- 퀘스트 DB 저장
- HUD 갱신 이벤트 발행
- 실패 항목 재시도 큐 등록
- TODO 확정 이벤트 수신

---

## 3. 입력 / 출력 (I/O Contract)

### 3.1 Input

| 필드                    | 타입        | 필수 | 비고                                                       |
| ----------------------- | ----------- | ---- | ---------------------------------------------------------- |
| `todos`                 | TodoRef[]   | ✅   | 처리 대상 당일 TODO 참조                                   |
| `characters`            | Character[] | ✅   | 사용자 보유 캐릭터 목록                                    |
| `remaining_daily_quota` | int         | ✅   | 남은 일일 생성 가능 수 (호출자가 카운터에서 조회하여 전달) |

**TodoRef:** `todo_id`만 가진다. **TODO 제목/내용은 입력에 포함하지 않는다** (C5 강제).

**Character:** `character_id`, `name`, `personality`, `speech_style`, `appearance_keywords`.

### 3.2 Output

```
QuestDistributionResult
├── generated: GeneratedQuest[]
│   ├── character_id
│   ├── todo_id
│   └── quest_text
└── skipped: SkippedItem[]
    ├── todo_id
    └── reason  (llm_failure 등)
```

## 4. 제약사항 (Constraints)

| ID  | 항목                        | 값                                                                                              |
| --- | --------------------------- | ----------------------------------------------------------------------------------------------- |
| C1  | 생성 수 상한                | 입력 TODO 수와 남은 일일 생성 가능 수 중 작은 값                                                |
| C2  | TODO ↔ 퀘스트 ↔ 캐릭터 매핑 | **1 : 1 : 1**                                                                                   |
| C3  | 같은 라운드 내 캐릭터 중복  | **금지**                                                                                        |
| C4  | 라운드 정의                 | 보유 캐릭터를 모두 1회씩 소진하면 1라운드 종료, **다음 라운드부터 풀 리셋**                     |
| C5  | 퀘스트 내용                 | TODO 내용과 **무관**, 캐릭터 페르소나/외형 기반 (입력에서 TODO 내용을 제외하여 구조적으로 강제) |

### 4.1 라운드 로직 예시 (C3, C4)

보유 캐릭터 3명, 처리할 TODO 5건인 경우:

- 1라운드: A → B → C 각 1회 (3건 처리)
- 2라운드 시작 (풀 리셋): A → B 각 1회 (2건 처리, 총 5건)

라운드 상태는 **단일 호출 내에서만 유효**. 다음 호출은 새 라운드로 시작.

## 5. 노드별 책임

### 5.1 처리 대상 결정

- 처리할 TODO 수는 입력 TODO 수와 남은 일일 생성 가능 수 중 작은 값 (C1)
- 처리할 항목이 없으면 빈 결과로 즉시 종료

### 5.2 캐릭터 풀 초기화

- 입력 캐릭터 전체를 무작위 순서로 풀에 채움
- 보유 캐릭터가 0명이면 빈 결과로 즉시 종료

### 5.3 캐릭터 풀 체크 / 리셋

- 풀이 비면 보유 캐릭터 전체로 재셔플 리셋 (C4)
- 외부 데이터 접근 없이 인메모리에서만 처리

### 5.4 캐릭터 선택

- 풀에서 한 명을 꺼내며 동시에 풀에서 제거 (C3 보장)
- "선택"과 "제거"가 원자적이어야 라운드 의미가 유지됨

### 5.5 퀘스트 컨텍스트 조립

- LLM 입력에는 캐릭터 프로필만 담음
- TODO 식별자는 결과 매핑 목적으로만 보유 (LLM 프롬프트에 미주입)
- **C5 강제:** 입력 자체가 TODO 내용을 포함하지 않으므로 구조적으로 주입 불가

### 5.6 LLM (Quest Text Generator)

- 출력: 퀘스트 텍스트 단일 필드 (구조화 출력)
- 프롬프트 원칙:
  - 캐릭터 1인칭 혼잣말 톤 (메인화면 말풍선 UX와 일치)
  - 페르소나/외형/말투 반영
  - TODO 내용 추측·언급 금지
- 재시도: 최대 2회. 모두 실패 시 해당 TODO를 실패 결과에 추가.

### 5.7 결과 누적

- 성공 항목은 성공 목록에, 실패 항목은 실패 목록에 누적
- 풀에서 이미 꺼낸 캐릭터는 LLM 실패 시에도 풀로 복귀하지 않음 (라운드 의미 유지)

## 6. 에러 처리

에이전트 내부에서 처리하는 것:

| 상황                                   | 처리                                                                |
| -------------------------------------- | ------------------------------------------------------------------- |
| 보유 캐릭터가 없는 경우                | 빈 결과 반환 (예외 아님)                                            |
| 남은 일일 생성 가능 수가 0 이하인 경우 | 빈 결과 반환 (예외 아님)                                            |
| LLM 호출 실패                          | 최대 2회 재시도 후 해당 TODO만 실패 결과에 추가, 다음 항목으로 계속 |
| 구조화 출력 파싱 실패                  | LLM 재시도와 동일 처리                                              |

호출자가 처리할 것 (본 에이전트 범위 밖):

- 저장 실패 시 카운터 보정
- HUD 이벤트 전송 실패 시 재시도
- `skipped` 항목의 백오프 재처리

## 7. 결정사항 (구현 spec 반영)

설계 spec(`docs/superpowers/specs/2026-05-25-quest-generation-design.md`) §10 에서 일괄 결정.

| # | 항목 | 결정 |
|---|---|---|
| 1 | 퀘스트 텍스트 길이 | **80자** (Pydantic `max_length=80` + 프롬프트 명시) |
| 2 | 캐릭터 풀 셔플 시드 | `shuffle_seed: int \| None` 옵션 주입 (운영 None, 테스트 고정값) |
| 3 | TODO 처리 순서 | 입력 리스트 순서 보존 |
| 4 | LLM 호출 동시성 | 순차 (Haiku rate limit·일 5회 throttling 고려 시 충분) |
| 5 | LLM 재시도 횟수 | 2회 (총 3시도, AI_RULES §3 기본값) |
