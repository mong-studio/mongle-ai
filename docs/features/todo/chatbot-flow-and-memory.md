# 챗봇은 어떻게 대화하고 기억할까? 🏡

> **이 문서가 하는 일**: 지금 `planner`(멀티턴)와 `todo`(싱글턴) 챗봇이 어떻게 대화를 진행하는지,
> 그리고 "방금 한 말"과 "오래 기억할 말"을 어떻게 저장하는지를 **아주 쉽게** 설명해요.
> 채팅 리팩토링을 시작하기 전에 이 그림을 먼저 머릿속에 넣어두면 좋아요.
>
> 코드를 직접 고칠 사람을 위해, 문단마다 📎 **파일 위치**를 같이 적어뒀어요.

---

## 0. 한 줄 요약

> 우리 마을엔 **챗봇이 두 명** 있어요.
> 한 명은 **"한 방 봇"**(todo), 한 명은 **"수다 봇"**(planner, 마을 이장님)이에요.
> "한 방 봇"은 기억이 아예 없고, "수다 봇"은 **지금 대화만** 잠깐 기억해요(서버 끄면 사라짐).
> **오래 기억(취향)** 은 챗봇이 아니라 **앱(클라이언트)** 이 들고 다녀요.

---

## 1. 챗봇이 두 명이에요

### 🥄 "한 방 봇" — `todo` (싱글턴)

장난감 자판기 같아요. 동전(문장) 넣으면 → 장난감(할 일 목록)이 바로 나와요. **대화는 없어요.**

```
사용자: "오늘 결과서 내고 운동 다녀올거야"
  ↓
한 방 봇: [전처리 결과서 제출 / 운동가기]  ← 끝!
```

- 흐름: `validate`(글자 수 확인) → `task_splitter`(문장을 할 일로 쪼갬) → `date_router`(오늘이면 TODO, 미래면 캘린더) → 끝
- **기억이 전혀 없어요.** 매번 처음 만난 사람처럼 굴어요.
- 📎 `agents/todo_creation/todo/pipeline.py`, API는 `POST /v1/todo/generate`

### 🗣️ "수다 봇" — `planner` (멀티턴, 이장님)

마을 이장님이에요. 큰 목표("시험 준비할래")를 말하면, **부족한 걸 되물어보고**, 날짜별 계획을 같이 짜줘요.

```
사용자: "정처기 시험 준비하고 싶어"
  ↓
이장님: "필기(7월 5일)야, 실기(8월 17일)야?"   ← 되물어봄!
  ↓
사용자: "필기"
  ↓
이장님: [7일짜리 공부 계획표]   ← 완성!
```

- 📎 `agents/todo_creation/planner/pipeline.py`, API는 `POST /v1/todo/chat`

아래부터는 **수다 봇(이장님)** 이야기예요. 리팩토링의 핵심이 여기거든요.

## 2. 이장님은 어떤 순서로 대화할까?

이장님은 안에 **작은 미로(그래프)** 가 있어요. 손님 말이 들어오면 이 미로를 지나가요.
📎 미로 설계: `agents/todo_creation/planner/graph.py`

```
                            [START]
                               │
                          ┌────────┐
                          │validate│  글자 수 같은 기본 검사
                          └────────┘
                               │
                          ┌─────────┐
                          │ planner │  "이 말로 계획 짤 수 있나?" 판단
                          └─────────┘
                          ╱    │     ╲
                     충분     부족      엉뚱한 말
                       │       │          │
              ┌──────────────┐ ┌──────────┐ ┌─────────────┐
              │plan_generator│ │ follow_up│ │ out_of_scope│
              │ 계획표 만들기 │ │ 되묻기   │ │ "난 계획봇야"│
              └──────────────┘ └──────────┘ └─────────────┘
                       │            │              │
                    [END]      (답 기다림)        [END]
                                    │
                              답이 오면 다시 planner 로 돌아감 ↺
```

### 각 방이 하는 일

| 방 | 하는 일 | 📎 파일 |
|----|---------|--------|
| **planner** | 손님 말을 보고 "계획 가능?/정보 부족?/엉뚱?" 결정. 두뇌 역할. | `nodes/planner.py` |
| **follow_up** | 부족하면 질문 1개 만들고 **잠깐 멈춰서** 손님 답을 기다림 | `nodes/follow_up.py` |
| **plan_generator** | 정보 충분하면 날짜별 계획표 + 태그 만들기 | `nodes/plan_generator.py` |
| **out_of_scope** | "날씨"처럼 계획과 상관없는 말엔 정해진 안내문만 답함 | `nodes/out_of_scope.py` |

### "잠깐 멈춤"이 신기해요 (interrupt)

이장님이 되물을 때, 프로그램이 **그 자리에서 일시정지**해요(`interrupt`). 손님이 답을 보내면 **멈췄던 그 자리에서** 다시 시작해요. 게임 "이어하기"랑 똑같아요.
📎 `nodes/follow_up.py:27` 의 `interrupt(question)`, 이어하기는 `pipeline.py:57` 의 `Command(resume=...)`

### 똑똑한 지름길도 있어요

손님이 계획을 보고 **"좋아", "응", "그렇게 할게"** 라고 하면, 이장님은 **AI를 다시 부르지 않고** 방금 만든 계획표를 그대로 다시 줘요. (돈·시간 절약)
📎 `pipeline.py:21` 의 `_ACCEPT_MESSAGES` 목록, `pipeline.py:61`

## 3. 기억 ① 단기기억 — "방금 한 대화" 🧠

> **비유**: 이장님 책상 위 **포스트잇**. 지금 손님이랑 나눈 말을 적어둬요.
> 근데 이 포스트잇은 **이장님 머릿속에만** 있어요. 종이에 옮겨 적지 않아요.

- 대화는 `history`(말풍선 목록)에 쌓여요. `[손님: ..., 이장님: ..., 손님: ...]`
- 이걸 들고 있는 건 **`MemorySaver`** 라는 상자예요. `thread_id`(대화방 번호)로 구분해요.
  📎 `graph.py:15` 의 `_checkpointer = MemorySaver()`
- 다음 손님 말이 오면, 이장님은 이 `history`를 **통째로 AI에게 같이 보여줘요**: "지금까지 이런 얘기 했는데, 이번 말은 무슨 뜻이야?"
  📎 프롬프트: `adapters/todo_creation/_prompts.py:109` (`최근 대화(JSON): {history}`)

### ⚠️ 단기기억의 약점

1. **서버를 끄면 사라져요.** `MemorySaver`는 컴퓨터 **메모리(RAM)** 에만 있어요. 재배포·재시작하면 대화가 증발해요.
2. **서버가 여러 대면 안 통해요.** 1번 손님이 A서버에서 시작했는데 다음 말이 B서버로 가면, B서버엔 포스트잇이 없어요. (지금은 사실상 서버 1대 전제)
3. **대화가 길어질수록 무거워져요.** `history`를 **전부** AI에게 보내요. 말이 20번 오가면 그 20개를 매번 다 보냄 → 느리고 비싸요.
4. **요약 기능이 없어요.** 코드에 `memory_summary`라는 빈칸이 있지만 **아무도 안 채워요**(죽은 칸). `recent_turns`(최근 6개만)도 만들어는 두는데 정작 AI엔 전체 `history`를 보내요.
   📎 빈칸: `planner/state.py:19` (`memory_summary`), `nodes/follow_up.py:36` (`recent_turns`)

## 4. 기억 ② 장기기억 — "이 손님은 이런 사람" 📒

> **비유**: 손님 취향 수첩. "이 분은 **저녁 공부**를 좋아하고, **평일 1시간**만 가능하구나."
> 근데 중요한 반전: **이 수첩은 이장님이 안 갖고 있어요. 손님이 직접 들고 다녀요.**

장기기억은 이렇게 흘러요:

```
앱(클라이언트)이 수첩을 보관
        │  매번 대화할 때 같이 보냄
        ▼
   user_profile_memory  ──→  이장님이 읽고 계획에 반영
        ▲
        │  계획 만들 때 "이런 취향 같던데?" 하고 메모 제안
   personalization_patch  ←── 이장님이 출력으로 돌려줌
        │
   앱이 받아서 수첩 업데이트 (저장은 앱 책임!)
```

- **들어올 때**: `user_profile_memory`(취향 JSON)를 앱이 요청에 실어 보내요.
  📎 입력 스키마: `agents/todo_creation/schemas.py:77`
- **나갈 때**: `plan_generator`가 "이 손님 이런 취향 같아요" 하고 `personalization_patch`를 만들어 돌려줘요.
  📎 `nodes/plan_generator.py:49`, 프롬프트: `_prompts.py:158`
- 취향 JSON 예시 (📎 `docs/features/todo/planner_memory.md` 의 합성 예시):
  ```json
  {
    "preferences": ["저녁 공부 선호", "짧은 TODO 선호"],
    "constraints": ["평일 1~2시간 가능"],
    "planning_style": ["실전 문제 중심"]
  }
  ```
- **일부러 저장 안 하는 것**: AI 답변 원문, 전체 채팅 로그, 잡담. (취향 요약만 남겨요 — 개인정보·용량 관리 때문)

### ⚠️ 장기기억의 약점

1. **서버는 저장을 안 해요.** 받기만(`patch` 출력) 하고, **진짜 보관은 앱한테 떠넘겨요.** 앱이 안 하면 장기기억은 없는 셈.
2. **수첩이 무한정 커질 수 있어요.** "취향 추가"만 있고 **합치기/중복 제거/오래된 거 지우기** 규칙이 없어요. AI가 비슷한 말을 계속 새로 추가하면 수첩이 뚱뚱해져요.
3. **검증이 없어요.** `patch`가 어떤 모양이어야 하는지 코드로 강제하지 않고 "프롬프트로 부탁"만 해요. 이상한 게 들어올 수 있어요.

## 5. 지금 좀 아쉬운 점들 (리팩토링 후보) 🔧

쉬운 말로, **급한 순서대로** 적어요.

### 🔴 크게 고치면 좋은 것

1. **단기기억이 RAM에만 있음 (가장 중요).**
   `MemorySaver` → **Redis나 DB 기반 체크포인터**로 바꾸면, 서버를 꺼도/여러 대여도 대화가 안 끊겨요.
   📎 `graph.py:15`

2. **장기기억 저장 주인이 없음.**
   `personalization_patch`를 받아 **서버 DB(JSON 컬럼)에 합쳐 저장**하는 자리를 만들어야 해요. "추가만"이 아니라 "합치고/중복 빼고" 규칙(merge)도 필요해요.

3. **대화가 길면 비싸짐.**
   전체 `history` 대신 **최근 몇 개 + 요약(`memory_summary`)** 을 보내도록 바꾸면 빠르고 싸져요. 지금 `recent_turns`/`memory_summary` 빈칸을 진짜로 쓰면 돼요.

### 🟡 중간 정리거리

4. **AI랑 규칙(if문)이 같은 결정을 두 번 해요.**
   `planner.py` + `goal_rules.py`에 한국어 조사 잘라내는 정규식, "엉뚱하다고 오판하면 되살리기(`build_recovery_goal`)" 같은 **임시방편 규칙이 잔뜩** 쌓여 있어요. AI 판단을 믿을지/규칙으로 덮을지 **경계를 정리**하면 훨씬 단순해져요.
   📎 `planner/goal_rules.py`, `nodes/planner.py:60`

5. **"좋아/응" 같은 수락어가 손코딩 목록이에요.**
   `_ACCEPT_MESSAGES`에 "ㅇㅋ", "그래", "좋네" 같은 건 빠져 있어요. 손님이 다르게 말하면 AI를 괜히 또 불러요.
   📎 `pipeline.py:21`

6. **시험 날짜 조회(enrichment)가 미로에 안 연결돼 있어요.**
   `enrichment.py`(정처기 시험일 같은 거 찾아주는 기능)가 만들어져 있고 질문 프롬프트도 그걸 기대하는데, **정작 그래프(`graph.py`)엔 그 방이 없어요.** 연결이 끊긴 부품이에요.
   📎 만든 것: `nodes/enrichment.py` / 안 쓰는 곳: `graph.py`

7. **이름이 문서랑 코드가 달라요.**
   설계 문서는 `session_id`, 코드는 `thread_id`. 통일하면 헷갈림이 줄어요.
   📎 문서 `CLAUDE.md` §2.2 vs `schemas.py:76`

### 🟢 작은 낭비

8. **목표 태그(goal_tag)를 두 번 만들어요.**
   `planner` 단계에서 한 번(`parsed_goal.goal_tag`), `plan_generator`에서 또 한 번(`generate_goal_tag`) AI를 불러서 덮어써요. 한 번이면 충분해요.
   📎 `nodes/plan_generator.py:24`

9. **요약 길면 그냥 다시 만들어요.**
   1500자 넘으면 **똑같은 입력으로 한 번 더** AI를 불러요. 짧아진다는 보장이 없는데 돈만 더 써요.
   📎 `nodes/plan_generator.py:30-31`

10. **싱글턴/멀티턴 통합이 어중간해요.**
    `state.py` 주석은 "single/multi를 한 그래프로 합쳐 `date_router`로 모은다"고 적혀 있는데, 실제로 planner는 **자기만의 그래프**를 쓰고 `date_router`를 안 거쳐요(계획표를 자기가 직접 오늘/미래로 나눔). 의도와 코드가 달라요.
    📎 `agents/todo_creation/state.py:1-8` vs `nodes/plan_generator.py:35-42`

## 6. 리팩토링 시작할 때 추천 순서 🪜

1. **단기기억을 영속화** (Redis/DB 체크포인터) → 대화 안 끊기게 (1번)
2. **장기기억 저장+합치기** 자리 만들기 → 진짜 개인화 가능하게 (2번)
3. **history 다이어트** (요약/최근 N개) → 빠르고 싸게 (3번)
4. **규칙 vs AI 경계 정리** → `goal_rules.py` 임시방편 걷어내기 (4번)
5. 나머지 작은 낭비들(8·9·10) 정리
