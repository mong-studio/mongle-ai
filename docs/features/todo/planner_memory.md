# 플래너 메모리 관리

## 목표

멀티턴 플래너는 현재 대화는 기억해야 하지만, AI 답변 원문과 전체 채팅 로그를 DB에 저장하지 않는다.
DB에는 나중에 개인화 플랜을 만들 때 필요한 사용자 성향 요약만 JSON으로 저장한다.

## 현재 대화 메모리

- 현재 진행 중인 채팅은 LangGraph `MemorySaver`가 관리한다.
- 저장 내용은 프로세스 메모리에만 있다.
- 서버 재시작, 배포, worker 변경이 있으면 현재 대화 상태는 사라질 수 있다.
- 이 메모리는 진행 중인 follow-up, 직전 플랜, 수정 요청 처리에 사용한다.

## 장기 개인화 메모리

장기 개인화는 전체 대화가 아니라 요약된 JSON만 저장한다.

예시:

```json
{
  "preferences": ["저녁 공부 선호", "짧은 TODO 선호"],
  "constraints": ["평일 1~2시간 가능"],
  "weak_areas": ["DP"],
  "planning_style": ["실전 문제 중심"]
}
```

이 JSON은 다음 플랜 생성 때 프롬프트에 함께 넣어 사용자에게 맞는 계획을 만드는 데 사용한다.

## 저장하지 않는 것

- AI 답변 원문
- 전체 채팅 로그
- 플랜 생성과 관련 없는 잡담
- 날씨, 일반 지식 질문처럼 플래너 범위를 벗어난 입력

## 왜 JSON인가

- 필드별 수정과 검증이 쉽다.
- RDB JSON 컬럼에 저장하기 좋다.
- LLM에게 보낼 때는 Markdown처럼 읽기 쉬운 텍스트로 렌더링할 수 있다.
- 사용자 삭제 요청이나 개인정보 관리에 대응하기 쉽다.

## 관련 없는 입력 처리

사용자가 `오늘 날씨가 뭐야?`처럼 플랜과 관련 없는 질문을 하면 플랜을 생성하지 않는다.
대신 플래너 챗봇임을 안내하고, 목표·기한·가용 시간 같은 플랜 정보를 입력하도록 유도한다.

## 운영 확장

현재 대화까지 서버 재시작 후에도 유지해야 한다면 `MemorySaver`를 Redis 또는 외부 checkpointer로 교체한다.
장기 개인화는 RDB에 JSON으로 저장하는 것이 적합하다.
