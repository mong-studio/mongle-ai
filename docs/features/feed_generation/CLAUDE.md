## 1. 목적 (Goal)

캐릭터에게 분배된 퀘스트가 수행된 시점에, 그 캐릭터가 퀘스트를 수행하는 모습의 **이미지**와 캐릭터 말투로 작성된 **캡션**을 함께 생성하여 피드 게시물 형태로 반환한다.

생성 결과만 반환한다. 저장·이벤트 발행은 호출자 책임.

---

## 2. 책임 범위

### 2.1 본 에이전트가 수행하는 일

- 입력 검증
- 이미지 생성 컨텍스트 조립
- VLM 호출 (이미지 생성)
- 캡션 컨텍스트 조립 (이미지 결과 반영)
- LLM 호출 (캡션 생성)
- 출력 길이 / 언어 제약 검증
- 피드 객체 구성 및 반환

### 2.2 본 에이전트가 수행하지 않는 일 (호출자 위임)

- 캐릭터 DB 조회 (캐릭터 정보를 입력으로 주입받음)
- TODO 완료 이벤트 수신
- 생성 이미지의 영구 저장 (Object Storage)
- 피드 DB 저장
- 알림/토스트 이벤트 발행

---

## 3. 입력 / 출력 (I/O Contract)

### 3.1 Input

| 필드        | 타입      | 필수 | 비고                                                  |
| ----------- | --------- | ---- | ----------------------------------------------------- |
| `quest`     | Quest     | ✅   | 수행 완료된 퀘스트 정보                               |
| `character` | Character | ✅   | 퀘스트 담당 캐릭터 정보 (호출자가 DB에서 조회해 주입) |

**Quest:** `quest_id`, `quest_text` (캐릭터에게 부여된 퀘스트 내용)

**Character:** `character_id`, `name`, `personality`, `speech_style`, `appearance_keywords`

### 3.2 Output

```
GeneratedFeed
├── character_id
├── quest_id
├── image           (생성된 이미지 데이터 또는 임시 참조)
└── caption         (한글 140자 이내)
```

이미지는 영구 저장 책임이 호출자에게 있으므로, 에이전트는 **임시 형태**(예: 바이너리 데이터 또는 임시 URL)로 반환한다.

---

## 4. 제약사항 (Constraints)

| ID  | 항목                 | 값                                                       |
| --- | -------------------- | -------------------------------------------------------- |
| C1  | 캡션 언어            | **한글**                                                 |
| C2  | 캡션 길이            | **140자 이내**                                           |
| C3  | 캡션 톤              | 캐릭터 페르소나 / 말투 반영                              |
| C4  | 캡션 내용            | 해당 캐릭터의 퀘스트 내용에 관련                         |
| C5  | 이미지 내용          | 캐릭터가 퀘스트를 수행하는 모습                          |
| C6  | 이미지 ↔ 캡션 일관성 | 캡션 생성은 생성된 이미지 정보를 반영해 작성 (직렬 의존) |

---

## 5. 노드별 책임

### 5.1 이미지 생성 컨텍스트 조립

- VLM에 전달할 프롬프트 구성
- 포함: 퀘스트 내용, 캐릭터 외형 키워드, 페르소나(분위기 톤 결정용)
- 캐릭터의 시각적 정체성 유지를 위해 외형 키워드를 항상 반영

### 5.2 VLM (이미지 생성)

- 입력: 위 컨텍스트
- 출력: 캐릭터가 퀘스트를 수행하는 모습의 이미지 (C5)

### 5.3 캡션 컨텍스트 조립

- LLM에 전달할 프롬프트 구성
- 포함: 퀘스트 내용, 캐릭터 말투, 페르소나, **생성된 이미지에 대한 묘사**
- C6 강제: 캡션이 이미지 내용과 어긋나지 않도록 이미지 정보를 반드시 함께 전달

### 5.4 LLM (캡션 생성)

- 출력: 한글 캡션 단일 필드 (구조화 출력)
- 프롬프트 원칙:
  - 캐릭터 말투로 작성 (C3)
  - 한글로만 작성 (C1)
  - 140자 이내 (C2) — 프롬프트에 명시
  - 1~2줄 정도의 짧은 글
  - 퀘스트 내용과 연결 (C4)

### 5.5 피드 객체 구성

- 이미지, 캡션, 캐릭터 id, 퀘스트 id를 묶어 출력 객체 구성

## 6. 실패 처리

본 에이전트는 다음 상황을 **실패로 간주**하고 호출자에게 알린다. 구체적인 실패 대응(재시도, 백오프 등)은 호출자가 결정한다.

| 상황                                 | 의미                                         |
| ------------------------------------ | -------------------------------------------- |
| VLM 호출 실패                        | 이미지 생성 불가 — 캡션 단계로 진입하지 않음 |
| LLM 호출 실패                        | 캡션 생성 불가                               |
| 캡션이 140자를 초과한 경우 (C2 위반) | 출력 검증 실패                               |
| 캡션이 한글이 아닌 경우 (C1 위반)    | 출력 검증 실패                               |

호출자가 처리할 것:

- 생성 이미지의 Object Storage 저장
- 피드 DB 저장
- 사용자 알림/토스트
- 실패 시 재처리 정책

---

## 7. 미결 사항

본 에이전트 범위 내에서 결정이 필요한 항목:

1. **이미지 반환 형태** — 바이너리 데이터로 반환할지, 에이전트가 임시 위치에 저장하고 임시 URL을 반환할지
2. **VLM 모델 선택 및 입력 방식** — character_generation에서 사용하는 이미지 생성 파이프라인(ControlNet + LoRA + SDXL)을 재사용할지, 별도 모델을 쓸지
3. **캐릭터 정체성 유지 강도** — 캐릭터의 기존 생성 이미지를 참조 이미지로 함께 넣을지(Img2Img), 외형 키워드만 텍스트로 넣을지(Text2Img)
4. **이미지 묘사를 어떻게 캡션 LLM에 전달할지** — VLM이 별도 묘사 텍스트를 함께 산출할지, 캡션 LLM이 멀티모달이라 이미지를 직접 받을지
